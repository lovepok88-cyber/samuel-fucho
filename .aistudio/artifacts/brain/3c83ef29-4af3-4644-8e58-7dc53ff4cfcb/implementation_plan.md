# 系統櫃尺寸丈量與案場管理系統 (Cabinet Measurement & Job Site Sync)

為系統櫃工程團隊量身打造的尺寸丈量、圖面比對與案場管理平台。整合主管與員工權限控制、案場建立與刪除、PDF 施工圖線上瀏覽器、以及以毫米 (mm) 為基準的現場丈量 vs 規劃尺寸即時差值比對與 2D 比例圖解。

### User Review & Critical Decisions

> [!IMPORTANT]
> 依據確認需求，系統將實作以下規範：
> - **安全與密碼規範**：主管帳號為「阿耀」，密碼為「0311」。依使用者明確指示，登入介面**絕不包含任何密碼提示或密碼範例文字**。一般員工可使用員工專屬帳號登入。
> - **權限邊界劃分**：一般員工可建立案場、上傳圖面、新增並填報丈量表；唯有主管（阿耀）具備刪除案場、全域覆核修改及系統參數微調的最高權限。
> - **圖面與尺寸核心**：單位一律強制為 **毫米 (mm)**；丈量表提供現場丈量與規劃圖面的自動差值（$\Delta$）運算、公差警示色標（合格/需微調/嚴重干涉）與 2D 櫃體比例輪廓比對圖；支援上傳並線上檢視 PDF 施工圖。
> - **即時資料同步**：採用伺服器持久化儲存與全端資料同步架構，跨裝置、跨分頁丈量數據零時差更新。

### 1. Overview & Core Concept

- **目標功能**：提供系統家具與裝潢木工現場丈量人員、設計師與工班主管一站式數位化工作台，消弭現場測量與工廠發包圖紙間的尺寸盲區。
- **目標使用者**：
  - **丈量工務/設計助理**：至案場攜帶雷射測距儀測量，直接於手機/平板/電腦登打 mm 尺寸，即時比對原設計規劃。
  - **主管 (阿耀)**：把關所有案場公差、覆核結構性尺寸異常、管理案場刪除與圖面發包。
- **核心價值**：自動計算正負公差（踢腳板、樑柱干涉、天地淨高、收邊條預留量），避免因尺寸落差導致工廠裁切錯誤或現場裝機碰撞。

#### A. 視覺語言與介面規範
- **色彩配置 (60-30-10)**：
  - 60% 主畫布：俐落中性灰白底色 (`bg-slate-50` / `bg-white`)。
  - 30% 結構面：石板灰卡片邊框 (`border-slate-200`)、表格高密度排列與深色導航列。
  - 10% 意圖重點：工業琥珀與藍灰專用主題（主管模式醒目標記、公差合規綠 `#16A34A`、需注意黃 `#D97706`、嚴重干涉紅 `#DC2626`）。
- **字型與排版**：
  - 標題與導航：俐落現代字體配搭。
  - 數值與尺寸：**全面強制套用等寬對齊數字 (`font-mono tabular-nums`)**，確保小數點與 mm 數值在垂直欄位中完全齊平。
  - 零藥丸（Zero-Pill）原則：中繼資料如狀態與時間戳記以優雅文字與點符號（`·`）分隔，不濫用彩色膠囊藥丸。

#### B. 關鍵互動流程
1. **驗證與角色切換**：
   - 預設訪客/未登入狀態需輸入帳號與密碼。
   - 主管輸入帳號「阿耀」與密碼「0311」後立即解鎖主管專屬功能（刪除案場按鈕、全域數值解鎖、系統備份）。
   - 一般員工登入後可完整建立案場、填報丈量表與上傳圖面，介面嚴格隱藏破壞性刪除操作。
2. **案場管理 (Job Sites)**：
   - 建立案場：輸入案場名稱、業主、聯絡電話、施作地址、空間類別（如玄關、客廳、主臥、多功能室）。
   - 案場列表：搜尋過濾、狀態快速篩選、總丈量進度進度條。
   - 刪除案場：主管身分二次確認彈窗，防止誤刪。
3. **PDF 施工圖在線檢視**：
   - 支援拖曳或上傳 PDF 檔案（CAD 施工圖、設計手繪圖）。
   - 整合即時 PDF 預覽（可自由放大縮小、旋轉、頁面切換、與丈量項目聯動參照）。
4. **毫米 (mm) 丈量比對矩陣與 2D 示意圖**：
   - 每個櫃體建立測量表項目（例如：E1主臥六門衣櫃、W2玄關懸空鞋櫃）。
   - 輸入規劃尺寸（寬度 W、高度 H、深度 D、踢腳板板高、天花淨高、大樑底高、大樑深度）。
   - 輸入現場丈量尺寸（雷射測距實測值、左牆高、右牆高、前深、後深、歪斜偏差值）。
   - 系統自動運算：
     $$\text{差值 } \Delta = \text{丈量尺寸} - \text{規劃尺寸}$$
   - 2D 櫃體比例視圖（動態 SVG）：以藍色虛線繪製圖面規劃輪廓，以實線繪製實測牆體與天花樑位，立即標示樑壓櫃體或側牆內傾夾角等干涉點！

### 3. Key Product Decisions & Trade-Offs

- **決策一：即時同步架構 (Real-Time Sync)**
  - *採用方案*：後端 Node/Express 提供 REST API + 長輪詢/事件同步，搭配前端快照與狀態持久化（檔案儲存於 `/data/storage.json`），確保重新整理或多裝置登入時資料即時同步不遺失。
  - *效益*：即使在案場網路不穩定時，前端亦提供 Optimistic UI 與離線快取，恢復連線立即與伺服器雙向對齊。
- **決策二：PDF 瀏覽與圖面儲存處理**
  - *採用方案*：支援本地 PDF 上傳轉換為持久儲存與內建檢視器，無需依賴易受跨域限制的外連服務，隨開隨看。
- **決策三：尺寸比較邏輯與公差防呆**
  - *採用方案*：建立系統櫃常用公差模型（例如：寬度負公差若小於規劃超過 5mm 需標記警示；天花淨高若低於規劃高度則為嚴重干涉阻擋；樑底高低於櫃頂則標示切角需求）。

#### 資料結構設計 (Schema)
1. **User / Role**:
   - `id`: string
   - `username`: "阿耀" (Supervisor) 或員工姓名/工號
   - `role`: `'supervisor' | 'staff'`
2. **Project / Site (案場)**:
   - `id`: string
   - `name`: string (e.g. 「信義極景 B棟 12F 蔡公館」)
   - `clientName`: string
   - `phone`: string
   - `address`: string
   - `floorRoom`: string
   - `status`: `'measuring' | 'verified' | 'warning' | 'ordered'`
   - `assignedStaff`: string
   - `pdfDrawings`: Array<{ id, name, size, uploadedAt, dataUrl }>
   - `createdAt`: string
   - `updatedAt`: string
3. **MeasurementSheet (丈量比對表)**:
   - `id`: string
   - `siteId`: string
   - `cabinetName`: string (e.g. 「玄關懸空鞋櫃」)
   - `category`: string (衣櫃、鞋櫃、電器櫃、書櫃、電視矮櫃、客製櫃)
   - `planned`: { width, height, depth, skirting, ceilingHeight, beamHeight, beamDepth, fillerAllowance }
   - `measured`: { width, height, depth, skirting, ceilingHeight, beamHeight, beamDepth, wallPlumbOffset, floorLevelOffset, notes }
   - `deviations`: 自動計算各項差值與嚴重度
   - `supervisorApproved`: boolean
   - `updatedBy`: string
   - `updatedAt`: string

### 5. Verification & Implementation Plan

1. **Phase 1: 後端伺服器與同步架構建置**
   - 建立 Express API 伺服器 (`server.ts`)，處理認證驗證（阿耀/0311）、案場 CRUD、丈量表 CRUD、PDF 檔案上傳與即時輪詢同步。
   - 整合 Vite 開發伺服器與 Express 代理。
2. **Phase 2: 前端權限、案場管理與 PDF 瀏覽器**
   - 實作員工/主管登入介面（嚴禁密碼提示）。
   - 實作案場列表、搜尋篩選、新增案場彈窗；僅主管顯示「刪除案場」操作。
   - 實作 PDF 施工藍圖預覽組件（具備縮放、翻頁、全螢幕與圖面備註）。
3. **Phase 3: 毫米 (mm) 丈量比對系統與 2D 比例圖解**
   - 實作系統櫃標準尺寸欄位輸入面板。
   - 差值運算與三級色彩公差警示（綠/黃/紅）。
   - 繪製 2D 向量立面圖，以藍線對比黑線呈現現場樑位壓頂或牆體歪斜。
4. **Phase 4: 全端編譯與測試驗證**
   - 透過 `compile_applet` 驗證 TypeScript 與打包建置無任何語法錯誤。
   - 驗證主管阿耀登入、一般員工登入、案場新增刪除、PDF 上傳與即時數值同步。
